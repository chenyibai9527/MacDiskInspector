# 用户使用手册

## 这个 App 会做什么

Mac Disk Inspector 读取用户选择目录中的文件系统元数据，包括路径、逻辑大小、已分配块、修改时间和硬链接标识，并在本机生成解释。

它不会：

- 打开或分析文件内容；
- 删除、移动或修改扫描到的文件；
- 自动执行终端命令；
- 使用管理员权限；
- 上传路径、文件名或统计数据。

## 第一次扫描

1. 打开 App，点击“选择目录”。
2. 建议先选择自己的用户目录，而不是整个系统卷。
3. 阅读目录选择窗口中的只读说明，然后开始扫描。
4. 扫描过程中可观察已访问项目、已计量空间和趋势图，也可以随时取消。
5. 扫描结束后先看“访问问题”，确认是否存在无权限目录。
6. 在“占用排行”选择 Finding，阅读规则置信度、原因和建议。
7. 只有在确认数据来源、用途和备份后，才在 Finder、目标 App 或终端中自行处理。

## 未签名社区版本如何打开

官网下载的未签名版本第一次启动时，macOS 可能阻止打开。确认下载域名和 SHA-256 后，前往“系统设置 → 隐私与安全性”，在安全区域选择“仍要打开”，再输入登录密码确认。不要为了安装本 App 全局关闭 Gatekeeper。

## 为什么全盘扫描很慢

磁盘容量不是主要决定因素，文件数量才是。一个包含几十万个小图片或缓存索引的目录，通常比单个数百 GiB 文件更慢。完整计量必须访问每个文件的元数据，macOS 权限检查、休眠磁盘和外置盘也会增加耗时。

全盘扫描会采用较浅的普通目录聚合，并继续识别深层已知规则，以减少内存和排序压力。即便如此，数百万文件仍可能需要较长时间。优先扫描怀疑目录通常更高效。

为避免包含大量符号链接或权限错误的卷耗尽内存，App 默认最多保留 5,000 条问题明细，同时继续统计问题总数，并在界面中说明省略数量。

## 如何理解空间数字

- **逻辑大小**：文件向应用呈现的长度。
- **已分配空间**：`lstat.st_blocks × 512`，更接近文件系统实际分配量。
- **候选空间**：值得进一步核对的数据体积，不是保证可释放空间。
- **APFS Clone**：多个不同文件可能共享物理块；逐文件已分配量相加可能大于真正独占空间。
- **稀疏文件**：逻辑大小可能很大，但实际只分配少量块。

## 如何理解访问问题

“无权限”不等于零占用。Mail、Messages、Safari、部分容器和系统目录可能受 TCC、ACL 或 POSIX 权限保护。App 会显示具体失败路径，不会用一个虚假的完整百分比掩盖缺口。

## 命令建议

命令只能来自 App 内置固定清单。点击后只复制到剪贴板，不会执行。执行前请：

1. 阅读完整命令；
2. 确认它属于目标工具；
3. 先运行检查命令；
4. 确认备份和退出目标应用；
5. 再由你自己决定是否在终端执行。

## 常见问题

### 为什么显示 0 B？

零表示文件系统报告当前没有已分配块，例如空文件。小于 1 KB 的非零值会按字节显示，不再舍入成 `zero KB`。

### 为什么候选空间和最后释放量不同？

应用可能正在使用部分数据；APFS Clone 可能共享块；清理后应用也可能立即重建缓存。候选空间只用于排序调查优先级。

### 为什么不提供一键清理？

相同目录名在不同应用、版本和账户中可能代表完全不同的数据。一键操作会把分类误差直接变成数据损失，因此不属于本项目目标。
