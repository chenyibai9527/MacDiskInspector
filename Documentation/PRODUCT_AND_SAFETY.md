# 产品定义与安全边界

## 产品承诺

Mac Disk Inspector 提供证据、解释和可验证建议，最终决策始终属于用户。默认行为是只读诊断，不以“可释放空间”制造紧迫感。

## 分类模型

| 类别 | 含义 | 默认处理 |
| --- | --- | --- |
| 可重新生成缓存 | 来源明确、通常可由工具重建 | 先验证，优先使用来源工具 |
| 应用内可管理数据 | 应用产生并应由应用管理 | 打开应用或 Finder 核对 |
| 用户数据 | 消息、文档、媒体、工作状态 | 高风险，不给删除命令 |
| 异常数据 | 体积/文件数与用途可能不相称 | 展示证据，要求人工确认 |
| 系统管理数据 | swap、系统区域、APFS 管理对象 | 禁止手动删除 |
| 未知数据 | 规则证据不足 | 不估算可释放空间 |
| 无权限访问 | TCC/ACL/POSIX 权限阻止读取 | 显示缺口，不推断 |

## 扫描器不变量

1. 只读取目录结构与文件元数据。
2. 使用 `lstat`，永不跟随符号链接。
3. 默认限制在用户选择目录所在卷。
4. 使用 `st_blocks × 512` 作为 allocated size，并保留 logical size。
5. 对多链接文件使用 `(device, inode)` 去重，避免重复计量。
6. 每轮循环检查取消状态。
7. 权限错误进入报告，不以零空间伪装为完整扫描。
8. 所有分析在本机内存完成，无网络代码、遥测或上传端点。

## 动作与命令边界

- App 自身不提供 Shell 执行器。
- 命令来自 `ActionAdvisor` 的静态字典，规则结果不能注入命令。
- 命令模板不拼接扫描路径。
- 高风险与禁止手动处理的数据不返回任何命令。
- 首批仅允许 `npm cache verify` 和 npm 官方缓存清理命令；两者都只复制到剪贴板。
- Finder 显示和打开目标 App 是显式用户动作。
- 不提供通用 `rm -rf`、`sudo` 或远程下发命令。

## 特殊对象

- `/private/var/vm` 与 swapfile：系统管理，禁止手动删除。
- `/System`、APFS 快照：系统管理，只指向系统/Apple 管理入口。
- 微信容器：可能含消息数据库，统一视为用户数据，高风险。
- Cursor `state.vscdb` 与 `.backup`：应用状态数据，不视为普通缓存。
- Chrome `OnDeviceModel`：可再获取但必须由 Chrome 上下文确认。
- Antigravity `browser_recordings`：标记异常数据；建议先核对录制任务和日期。

## 覆盖状态

App 不再显示看似精确的覆盖率百分比。一个无法访问的目录可能包含任意数量的文件和字节，按错误数量推导百分比会误导用户。

报告只声明：

- 本次是否发现访问缺口；
- 每个失败、符号链接和跨卷路径；
- 问题类型与系统错误。

主动跳过的符号链接和其他卷单独列出，不伪装成权限错误；无权限不等于零占用。

## 非目标

- 自动删除、移动到废纸篓或批量修复；
- 后台常驻扫描；
- 全盘索引数据库；
- 规避 TCC、请求管理员权限或安装 helper；
- 依据目录体积直接断言“安全可删”。
